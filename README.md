# Wolfdris

**Idris 2 with a Wolfram Language backend.** Write Idris, get dependent
types, and call the Wolfram Language library through typed wrappers — or
package your Idris code as a paclet that Wolfram notebooks can call.

> **Generated by an LLM.** All of the code in this repository — the
> compiler backend, the Wolfram Language runtime, the wrapper library,
> the scripts, the tests, the design notes (`CLAUDE.md`, `docs/`) and
> this README — was written by Claude (Anthropic's Claude Opus 5.5), an
> AI model, working in Claude Code. The human author chose the
> direction, made the design decisions when offered alternatives, and
> reviewed the work at checkpoints. It is tested (see below), but treat
> it as what it is: an experimental project written by an AI.

```
.idr source
    ↓  Idris 2 compiler (unmodified: elaboration, dependent types, totality)
    ↓  named case trees (Idris's intermediate representation)
    ↓  Wolfdris code generator
Wolfram Language (.wl)
    ↓
Wolfram Engine / Mathematica
```

Wolfdris is two things: a **code generator** that turns Idris programs into
Wolfram Language, and a **wrapper library** that gives Wolfram functions
Idris types. The deal: *reuse Wolfram's implementations, write the types
ourselves.* `Solve`, `LeastSquares` and `Integrate` are decades of work;
a typed wrapper around one is a few lines.

It is **not** a type checker for existing Wolfram code, and it is not
"Wolfram with types": you write `.idr` files, and Wolfram is a library you
call.

## What it looks like

**Types that say what Wolfram can't.** A Wolfram function returns a plain
list, so shape information is lost at every call. The wrappers measure or
check it and put it back into the type:

```idris
wlSelect      : Marshal a => (a -> Bool) -> Vect n a -> (p ** Vect p a)       -- p is measured
wlLinearSolve : Matrix n n -> Vect n Double -> Maybe (Vect n Double)          -- Nothing: no solution
wlRoots       : Vect (S d) Double -> Maybe (Vect d Complex)                   -- exactly d roots
wlTaylor      : (n : Nat) -> Expr -> String -> Expr -> Maybe (Vect (S n) Expr) -- exactly n+1 coefficients
```

A 3×3 system with a right-hand side of length 2 is a compile error.

**Numerics** (from [tests/polyfit](tests/polyfit/Main.idr)):

```idris
fit : (d : Nat) -> Vect (S m) Double -> Vect (S m) Double -> Vect (S d) Double
fit d xs ys = wlLeastSquares (map (powers d) xs) ys

main = do
  let cs = fit 3 xs ys                 -- [3.0, -2.5, -1.5, 1.0]
  case wlRoots cs of
    Just rs => printLn rs              -- the cubic's 3 roots, as Complex
    Nothing => putStrLn "leading coefficient is 0"
```

**Symbolic math** (from [tests/symbolic](tests/symbolic/Main.idr)) — Idris
builds the expression, Wolfram does the calculus:

```idris
x = var "x"
f = x ^ 2 * sin x

wlD f "x"                     -- x^2*Cos[x] + 2*x*Sin[x]
wlIntegrate f "x"             -- Just (-((-2 + x^2)*Cos[x]) + 2*x*Sin[x])
wlIntegrate (sin x / x ^ x) "x"   -- Nothing (no closed form)
wlSolve (x ^ 2) (-1) "x"      -- Just [-I, I]
wlExportPlot "f.png" f "x" (-3.0) 3.0
```

Expressions can only be built through typed functions, so `Sin[1, 2, 3]`
doesn't compile; results from Wolfram always come back, even with
functions Idris doesn't model (`Erf`, …), and can be inspected through a
typed `view`.

**Data** (from [tests/data](tests/data/Main.idr)) — every CSV row becomes a
typed record or is rejected with a reason:

```idris
record Sale where
  constructor MkSale
  region : Region          -- North | South | East | West, checked
  year   : Nat
  amount : Double
  note   : Maybe String

Marshal Sale where
  desc = record4 ("region", "year", "amount", "note") MkSale
                 (\s => (s.region, s.year, s.amount, s.note))

main = do
  Right rows <- wlImportCSV "sales.csv" | Left e => putStrLn e
  let (sales, bad) = validateRows {r = Sale} rows
  -- bad: [(5, "year: expected Nat, got \"abc\""), (8, "region: unknown region \"Mars\""), ...]
  for_ (wlGroupBy region sales) $ \(r, ss) => ...
```

**Calling Idris from a notebook** (from [tests/paclet](tests/paclet/Main.idr)):

```idris
fitEntry : Nat -> List Double -> List Double -> Either String (List Double)

main : IO ()
main = library
  [ fn3 "fit" "fit[d, xs, ys] fits a degree-d polynomial ..." fitEntry
  , fn1 "roots" "roots[coeffs] gives the roots ..." rootsEntry ]
```

```wolfram
PacletDirectoryLoad["path/to/PolyFit"]; Needs["PolyFit`"]
fit[3, xs, ys]                (* {3., -2.5, -1.5, 1.} *)
solve[{{1., 2.}}, {1., 1.}]   (* Failure["IdrisError", <|"MessageTemplate" -> "the matrix must have as many rows as b"|>] *)
```

Arguments are checked against the Idris types; bad input, a `Left` or a
crash comes back as a `Failure`, and the notebook's kernel carries on.

## Status

Experimental, but substantial and tested:

- **The backend** compiles all of Idris's primitives and runtime model
  (closures, laziness, IORefs, files, IEEE doubles, unlimited recursion
  depth). It passes **97–98 of 108** of Idris 2's own test programs run
  against it (the rest: `Data.Buffer`, processes, and two or three that
  exceed the time limit) — see [docs/conformance.md](docs/conformance.md).
- **16 tests** in `tests/`: differential tests (same output as Idris's
  Chez backend, byte for byte) and golden tests for the wrapper library,
  the paclet mode, symbolic math and data import.
- **Wrapper library** (package `wolfram`): list functions, linear
  algebra, symbolic calculus, data import and validation, charts and
  plots, paclet exports. Wrappers are added
  as programs need them; there is no attempt at a complete typed stdlib.

## Requirements

Developed and tested on **Windows 11 with WSL 2 (Ubuntu)**:

- **Wolfram**: Mathematica or the free Wolfram Engine, with `wolframscript`
  (tested with Wolfram Language 15.1). The Windows install is used from
  WSL; set `WOLFRAMSCRIPT` to point elsewhere. Other platforms should be
  close but are untested.
- **Idris 2 v0.8.0** with its compiler API, built from source by
  `scripts/build-idris.sh` (needs `chezscheme build-essential git libgmp-dev`).

Running a compiled program only needs Wolfram — no Idris.

## Quick start

Inside WSL, from the repository:

```bash
scripts/build-idris.sh        # once: Idris 2 v0.8.0 + its compiler API into ~/.idris2
scripts/build.sh              # the backend (build/exec/wolfdris) + the wolfram package

# compile and run a program
scripts/wolfdris --cg wolfram Hello.idr -o hello     # writes build/exec/hello.wl
build/exec/hello                                      # runs it with wolframscript

# programs that use the wrapper library
scripts/wolfdris -p wolfram --cg wolfram Main.idr -o main

# tests
scripts/test.sh               # all tests (~12 min), or name some: scripts/test.sh polyfit
scripts/conformance.sh        # Idris's own test suite (~35 min)
```

Each run pays ~14 s of Wolfram kernel startup.

## The wrapper library

| Module | What it gives |
|---|---|
| `Wolfram.FFI` | `Marshal` (Idris value ↔ Wolfram expression, checked), `toWL`, `fromWL`, `fromWLMaybe`, `fromWLEither`, `fromText`, `record1`…`record5`, `refine`, `WLExpr`, `Complex` |
| `Wolfram.List` | `wlSelect`, `wlMap`, `wlSort`, `wlLength`, `wlTotal` |
| `Wolfram.LinAlg` | `Matrix m n`, `wlDet`, `wlLinearSolve`, `wlLeastSquares`, `wlEigenvalues`, `wlRoots` |
| `Wolfram.Symbolic` | `Expr` and its typed builders (`var`, `+ - * / ^`, `sin`, `exp`, `pi`, …), `view` |

| `Wolfram.Export` | `library`, `fn1`/`fn2`/`fn3`: exports for paclets |

### Writing a wrapper

A wrapper is a `%foreign` declaration naming the Wolfram function, plus a
few lines of Idris that convert, call, and re-establish what the type
promises:

```idris
%foreign "wolfram:Select"
prim__select : WLExpr -> WLExpr -> WLExpr

wlSelect : Marshal a => (a -> Bool) -> Vect n a -> (p ** Vect p a)
wlSelect p xs = let ys : List a = fromWL (prim__select (toWL (toList xs)) (toWL p))
                in (_ ** fromList ys)
```

- `fromWL` **checks** the shape of what Wolfram returns and stops with a
  clear error (`expected List Integer, got {1, 2, x}`) instead of letting
  a wrong value in. Lengths are measured (`fromList`) or checked
  (`withLengthOf`), never assumed.
- Where Wolfram can fail, return a `Maybe`: Wolfram leaves a call it can't
  do unevaluated, and `fromWLMaybe` turns that into `Nothing`.
- The spec can be a small Wolfram expression instead of a name, for glue:
  `%foreign "wolfram:(#1 /. #2 -> #3 &)"`.
- A foreign function returning `Bool` must give `0`/`1` (`Boole[...]`),
  the runtime representation of `Bool`.

### Making a paclet

```bash
scripts/paclet.sh Main.idr PolyFit outdir     # outdir/PolyFit/{PacletInfo.wl, Kernel/PolyFit.wl}
```

`Main.idr`'s `main` registers the exports (`library [fn1 …, fn3 …]`).
The paclet carries its own copy of the runtime under its own contexts, so
several Idris paclets can be loaded into one kernel, and loading one
changes no global settings.

## How it works

- The backend consumes Idris's **named case trees** and emits one
  self-contained `.wl` file with the runtime (`support/wolfram/runtime.wl`)
  inlined.
- Generated code is in **continuation-passing style** with closure
  conversion, so Idris's deep recursion never grows Wolfram's stack.
- Idris values have their own runtime representation (constructors are
  `Con[tag, fields…]`); **marshalling** to and from ordinary Wolfram
  expressions happens only at the boundary, driven by a descriptor of the
  Idris type that the `Marshal` interface picks.
- Primitive operations follow the Chez backend's semantics exactly
  (fixed-width integer wrapping, Euclidean division, IEEE doubles with
  Wolfram's own `Infinity`/`Indeterminate`, Chez's `show` for doubles).

The full design log — every decision, the alternatives rejected, and the
Wolfram behaviours found along the way — is [CLAUDE.md](CLAUDE.md).

## Limitations

- **Slow.** Every small Idris function becomes several Wolfram calls
  (~1–3 µs each). Fine when Idris orchestrates and the heavy computation
  happens inside Wolfram functions; not for number crunching in Idris.
- **The trusted base is large.** Each wrapper asserts facts the type
  checker can't verify (Wolfram functions are black boxes). Runtime
  checks catch wrong shapes, not wrong meanings.
- **No interactive stdin** under `wolframscript -file` (piped input works).
- **Programs run on Windows**, not in WSL, in the tested setup: paths,
  environment and `prim__os` are Windows'.
- **No signed zero** (Wolfram has no `-0.0`).
- Paclet exports are pure functions of data so far (no `IO`, no symbolic
  arguments).
